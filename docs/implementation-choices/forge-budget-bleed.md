# Forge reads after #3710

#3710 changes per-prepare default-branch reads, per-subject forge refreshes, and checkout integration inspections. The cache is by service/repository, process local, pull on miss/expiry, six-hour monotonic success TTL; failures are not cached, classified UTC retry deadlines are cooldowns. Per-key locks coalesce concurrent misses; a short outer lock allocates keys. Idle expired entries are pruned at most once per minute. No wire or stored shape changes.

Repository cardinality is not separately specified in WORKLOAD.md. Use running_convoys (target 1,000; ceiling 10,000) as an illustrative distinct-repository upper estimate, not an owner-set repository bound. At an estimated 256 bytes per cache key, 10,000 keys use ~2.6 MB plus allocator/locks; hourly churn is limited to keys accessed during the last six hours plus a pruning minute. Cache hits hash one key and take one uncontended lock; pruning amortizes an O(repository count) pass per minute, ~167 entries/s at 10,000 keys. At 10,000 distinct keys the worst case still requires 40,000 successful lookups/day; cache does not claim to fit the shared 5,000/hour forge budget at every startup. Existing ForgeBudgets throttles remain unchanged.

Merged subjects use the existing replicated records and selection policy. New record reads use existing declared equality indexes: source/service/number membership for a bound batch, and the numeric subject index before canonical spelling selection in the refresher. All replica origins remain candidates, preserving whole-observation selection. A batch decodes its matching records rather than the namespace inventory. The refresher decodes K copies sharing the requested number, so repeated number collisions across many repositories are its remaining limit; resolving that without spelling assumptions belongs to observation identity #3654. No new durable schema/index is introduced. Existing repository/convoy inventory lists in the surrounding paths remain unchanged; they are not a new claim to meet the WORKLOAD ceiling. Its replacement belongs to the separate forge-access design (#3708/#3414). A merged refresh task exits; retained subjects have their own schedule and do not widen demanded groups. All merged fields are immutable owner-ruled facts. Closed subjects retain existing live behavior.

Checkout inspection reads the replicated PR state and SHA. Only mergedAt/baseRefName cross the forge boundary after merge, then existing evidence is reused. Active/Pending integration refresh returns to six hours; explicit deletion requests a fresh local inspection before its evidence gate. Validation carries ObservationError and uses a per-checkout in-memory delay (1s doubling to60s, reset on success) unless retry_at overrides it.


Candidate walk: unconditional reads waste paid calls on every controller resync. A single global async cache lock coalesces requests but lets one slow repository block all others, so use a short outer map lock and per-key async locks. A full replica or stored default-branch cache changes persistence without helping this key lookup; the owner requested an in-memory cache. Success TTL is six hours; UTC cooldowns preserve the parsed deadline without caching failed results.

Expiry: revisit cache cardinality and pruning if distinct repositories exceed the running-convoy illustration, or repository churn makes six hours of keys exceed the memory budget. The resolver trait keeps a future cache replacement internal. Replace inherited whole-kind observation listings when the separate forge-access work supplies its resident query seam.
