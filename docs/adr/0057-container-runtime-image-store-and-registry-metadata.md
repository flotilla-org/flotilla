# Container lifecycle, image storage, and registry metadata have separate interfaces

Container operations follow the host's detected capabilities and injected runner rather than assuming Docker at each daemon caller. `ContainerRuntime` owns the existing vessel lifecycle and bounded verification containers; `EnvironmentProvider` is its compatibility name for existing environment callers. `ImageStore` owns build, local inspection/inventory, content pull/push, archive save/load, tagging, and digest-addressed removal. Its operation context carries an admitted private auth directory and build context, while structured build/probe options hide CLI argv. Local config IDs and registry manifest digests remain distinct identities; callers verify delivered images against immutable build evidence.

Docker is the first adapter, constructed through the detector/factory/EnvironmentBag path. No binary assertion means unavailable, with no factory fallback that discovers a tool mid-operation. Podman and nerdctl can provide additional adapters without changing consumers; a remote BuildKit can implement image building while a different runtime provides vessels. We retain the environment handle's runner for execution inside an established vessel: that is a different execution environment from host image storage.

`RegistryClient` owns OCI distribution metadata over HTTP, independently of the host container CLI. It resolves declared credentials for every operation, exchanges tokens only with an admitted issuer, and binds scope to repository and read/delete action. HEAD/GET/DELETE require manifest digests; GET verifies content; tag listing remains mutable discovery, never frozen image identity. Pull/push content stays with ImageStore. Registry deletion has its own `image-delete` host grant so a push grant cannot authorize destructive metadata operations. Existing stored grants still decode. Out-of-repository authors are project-map resource manifests and delegated fleet ops repositories (ADRs 0044 and 0054); the additive action requires no change to their existing manifests, which retain their current meaning. A future deletion controller must declare its own new grant.

A combined Docker command runner would move literals without removing caller knowledge of Docker flags, formats, auth, and timeout cleanup. A combined registry/image interface would also force metadata users to depend on a locally installed runtime. We instead concentrate those details in adapters and extend the existing ast-grep CI rule to forbid direct Docker/podman/nerdctl/skopeo invocations elsewhere. Provider tests use injected processes and an enforcing in-process distribution stand-in, so the contract can be proved on hosts without Docker. No workflow edit is needed: the existing format job already runs the extended check and its tests.

Image inspection returns an optional identity: only a definite CLI not-found is absent, while timeouts, daemon errors and malformed output remain operational errors. Probe facts preserve unknown status and builds retry instead of rebuilding on those errors. Registry HEAD during content pull is advisory except for a definite missing manifest; the content adapter still enforces the declared credential and immutable reference, so Basic-auth registries and separately hosted token issuers retain their existing pull path. The metadata client itself supports Bearer with an explicitly admitted issuer, pins token scope exactly (including refusing challenge supersets), accepts GET without a digest header after checking the body hash, and uses a redirect-disabled production transport.

Private operation config deliberately excludes host-global contexts and credentials. Buildx must be installed system-wide; user-only CLI plugins and non-default host contexts are not inherited. Metadata operations retain independent short-lived no-auth directories rather than caching mutable CLI configuration across requests. Tag inspection does not infer a manifest from the first RepoDigest: only an exact pinned repository reference supplies that identity. Anonymous probes get generated names so timed-out containers can be removed just like explicitly named probes.
