# Lifecycle endings: stored-schema review checkpoint

The owner approved the Quint proposal at
[the recorded model ruling](https://github.com/flotilla-org/flotilla/pull/3819#issuecomment-6403492562).
This checkpoint supplies typed stored-shape declarations, generated DDL and a
compatibility recommendation. The stored schema and compatibility policy still
need their own look-over. Approval of PR #3794 does not approve this DDL.

```text
Requested -- failed attempt, GiveUp --> GaveUp(cause)
Requested or Realised -- Release --> Gone(Released)
Realised -- Vanish(Lost) --> Gone(Vanished(Lost))
Realised -- Vanish(Failed(reason)) --> Gone(Vanished(Failed(reason)))
```

The approved Quint files are unchanged in this stage. The running Rust machine,
edge payloads, production registries, read ports and bindings do not consume the
candidate shape. Its declarations are staged in
[`lifecycle::schema_review`](../../crates/flotilla-state-machines/src/machines/lifecycle/schema_review.rs).
The existing pre-readiness binding fix and shared Attempted/GiveUp recovery
remain separate from the unimplemented typed ending consumers.

## Compatibility recommendation for owner review

Recommend `Gone { ending: Option<Ending> }` in the stored representation:

- New operational Release/Vanish transitions always produce `Some(Ending)`;
  the operational model gains no Unknown event or ending variant.
- Accept a preceding-generation bare Gone as `ending: None` when its ending
  cannot be established. This is a terminal state with unknown history, not
  Released, Lost, Failed, a retry, or a live resource.
- A retained, validated final Release entry can establish Released. An older
  Vanish entry has no typed cause: it cannot establish Lost versus Failed or
  a failure reason. A snapshot may lack even that final entry. Retain the
  original records/evidence and leave the typed ending absent in these cases;
  do not fill it from an old status, an empty string, or a guessed cause.
- The new schema therefore permits all three ending columns to be null for
  Gone. Known Released/Vanished values still obey their full payload checks.
  This nullability is the concrete compatibility choice submitted here for
  approval, not an already-approved runtime policy.

| Input evidence | Recommended N+1 state |
|---|---|
| Bare Gone with a validated final Release | `Gone { ending: Some(Released) }` |
| Bare Gone with an old Vanish lacking a cause | `Gone { ending: None }`; retain the old Vanish evidence |
| Bare Gone from a snapshot without its final entry | `Gone { ending: None }` |
| N+1 Gone with a known typed ending | Preserve that exact ending and reason |
| N+1 Gone with an absent ending, restored or replicated | Preserve `None`, including in later generations |

The preceding-generation input decoder is a one-roll compatibility adapter;
its implementation is deferred. The absent ending in an imported N+1 row must
remain decodable beyond that roll while the row is retained. Do not remove
this representation merely because the older input decoder can be retired;
unknown history cannot become known with time. Any later retirement requires
an explicit policy for the remaining terminal records, not fabricated endings.

The current SQLite adapter rejects changed kind-table column layouts with
`KindTableDrift`; it has no in-place migration. Recommend an explicit,
versioned import/restore into a new store, retaining the old database until
verification succeeds. The adapter must decode N's schema and edge payloads,
translate the row without inventing a transition, preserve home/identity,
version and replication checkpoint semantics, and retain old log evidence.
An old Vanish payload needs its own legacy input representation rather than
being decoded as a new typed Vanish with a default cause. The exact import,
checkpoint and rollback mechanics require a separately reviewed implementation;
this preparation stage does not implement or authorize a migration or roll.

Required compatibility proof after schema approval: old Released with final
edge evidence, old Vanished without a cause, Gone seeded without a final edge,
and N+1 restore/replication of `ending: None`. Verify terminal refusal,
identity/version/checkpoint preservation and no fabricated log entries, plus
known Lost and Failed (including a genuinely empty or Unicode reason).

No out-of-repository source authors these engine lifecycle records. Their
requests are authored by the daemon's bindings and demand writers. This stage
does not change those producers or the resource API's stored shapes.

## Regeneration

From the repository root:

```sh
CARGO_BUILD_JOBS=1 cargo run -p flotilla-provisioning --example lifecycle_endings_schema --locked -- docs/proposals/lifecycle-endings
cargo test -p flotilla-provisioning --locked --test lifecycle_schema_review
```

Regenerate `generated-schema.diff` by concatenating `git diff --no-index`
between each file under `crates/flotilla-provisioning/tests/snapshots/` and its
candidate counterpart here: `provisioning.sql`, `crew.sql`,
`provisioning_schema_view.md`, `crew_schema_view.md`, in that order. A return
code of 1 means a diff was produced. Do not edit generated SQL or views by hand.

## Remaining checkpoint

Present these files for owner schema/compatibility review before implementing
machine transitions, decoders, table readers/writers/queries, read-port endings,
Vessel copy removal or compatibility import. The real Quint/Rust mismatch
remains visible until the approved model is implemented after that look-over.
After approval, replace the running declaration with the reviewed shape and
remove the staging module/generator rather than retain parallel authorities.
No merge, primitives enablement, migration or fleet roll is authorized here.
