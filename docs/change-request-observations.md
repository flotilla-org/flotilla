# ChangeRequest identity and convoy history

A ChangeRequest subject is `(service, scope, number)`. Resource names and replica origins are storage addresses, not additional subject identities. Observers write the canonical name from `change_request_record_name`; external records can use other names.

`select_change_requests` is the shared selection policy for the subject catalog, PM connector, and convoy explain. It selects a complete observation by the greatest state observation timestamp, then observing authority, canonical-name preference, namespace/name, and serialized status as a final deterministic tie-break. Missing status ranks below observed status. Local and replicated records follow the same policy. Receiving-host resource versions and synchronization timestamps do not affect selection. Unknown fields remain unknown; losing observations never fill them in. This avoids combining checks or review facts from different heads and prevents resource-list order from determining published facts.

Convoy history is combined across all records for a subject. `spec.subject_of` records the convoy namespace, name, host origin, relationship, role, project, and last-seen time. Repeated observations of the same link retain its greatest last-seen time. Unchanged links refresh last-seen at most once per hour, and otherwise skip spec writes; new links are recorded immediately. The refresher requires an explicit convoy-home origin. The convoy home captures declared and discovered links when demand is admitted and during refresh. History lives in the spec so ordinary forge status replacement cannot erase it. It replicates with the existing ChangeRequest observation resource. An absent history field decodes as an empty list for the previous stored generation (ADR 0047); no migration is required.

Requests with a producing link remain stored after their last demand is released unless merged or closed. Unknown forge state is retained conservatively; it does not produce an observed-open orphan badge. Startup restores monitoring of retained requests, including non-default namespaces. Monitoring checks replicated terminal observations even when another host owns the forge refresh. Collection failures retain monitoring and are logged. Per-subject locks serialize cleanup with admission without holding the global active-task lock during backend I/O. There is one retained refresh task per subject, with a fifteen-minute polling cadence; retained tasks do not subscribe to demand-only relay hints. A live demand restores the ordinary cadence. Retention has no age cutoff: ADR 0051 requires open work to remain visible until merged or closed. Terminal observation collects local records for that subject.

The catalog marks an observed open or draft request `flotilla.orphaned = true` when its history names a departed producing convoy. It keeps `flotilla.subject_of` and the relationship-specific reverse edges pointing to the historical convoy's exact entity identity. A terminal request without live or recent-landed subject links leaves the catalog. Historical edges do not synthesize a departed convoy entity.

ChangeRequest records are authored by daemon observers. There are no known out-of-repository manifest authors of this resource shape; existing external API authors can omit the new history field.
