{% block operating_instructions %}{{ super() }}For a GitHub destination, use the `pr-shepherd` skill to process reviews, check results, conflicts, fixes, and the claim's linked `## Decision ledger` comment. For a Forgejo destination, do not use that GitHub-only helper; use the injected Forgejo API credentials. Treat the ledger as review material: revise wrong choices through the ordinary review cycle and require the crew to update the ledger comment. A completion without a ledger is refused unless an operator explicitly forces it.
{% endblock %}
{% block delivery %}Process every item in every review of the bound pull request, including non-blocking, nit, minor, style, test-gap, and trailing-section findings. "No blocking issues" does not excuse another item. Reply to each finding with a fix and commit, concrete reasoning, or a filed follow-up issue number; leave none silent. After each push, check CI and new reviews. While checks are pending, report the PR URL and current state, then yield at the turn boundary. Flotilla delivers a new turn when checks at head settle (pass or fail), or actionable review feedback arrives. On that turn, inspect checks and reviews, fix failures caused by this PR, and continue shepherding. Use `flotilla crew stall` for real blockers such as CI failures outside this PR, unavailable credentials, missing access, or unresolved scope or decisions. After the re-review, check the forge's merge state. Rebase only when the forge reports a conflict with the target branch, or a required check fails because of a change that landed there; a pull request that is merely behind the target branch is ready as it is. After a rebase, repeat the checks and review handling. If checks are still pending when you reach settlement, report the PR state and yield at the turn boundary; flotilla wakes you when checks settle, and you then take the clean final snapshot. Report readiness and complete with `flotilla crew complete --message '<PR URL>'` only when the pull request is mergeable, checks pass, and review items are handled. If CI remains red for reasons outside this pull request, report the evidence and use `flotilla crew stall --reason <infra|scope|decision|access|other> --message '...'`, with `--propose <resume|reduce-scope|fail>` if useful. Do not merge the pull request. Run the applicable crew settlement command as your final act.{% endblock %}
{% block assignment %}Process all reviews and CI for the bound pull request through merge readiness against current main — with the `pr-shepherd` skill for a GitHub destination, or through the injected Forgejo API credentials for a Forgejo destination. Handle re-review before reporting the result and yielding. Once `flotilla crew complete` is accepted, your work is Done; a pending change request merge or convoy landing is a world condition, so do not stall over it. The convoy lands automatically after the merge.{% endblock %}
