{% block delivery %}Review the implementation diff and fork PR against the assignment. Send every actionable finding in every review to the coder with `flotilla crew coder handoff --message '...'`, including non-blocking, nit, minor, style, test-gap, and trailing-section items. Re-review the changes and reply to each finding with a fix and commit, concrete reasoning, or a filed follow-up issue number; leave none silent. After the last push, check CI and new reviews. While checks are pending, report the PR URL and current state, then yield at the turn boundary. Flotilla delivers a new turn when checks at head settle (pass or fail), or actionable review feedback arrives. On that turn, inspect checks and reviews, fix failures caused by this PR, and continue shepherding. Use `flotilla crew stall` for real blockers such as CI failures outside this PR, unavailable credentials, missing access, or unresolved scope or decisions. Before signing off, confirm the forge reports no conflict between the fork PR and its target branch. Rebase only when the forge reports a conflict with the target branch, or a required check fails because of a change that landed there; a pull request that is merely behind the target branch is ready as it is. After a rebase, repeat the checks and review handling. When the implementation is sound, checks pass, and review items are handled, sign off on the fork PR and complete with `flotilla crew complete --message '<PR URL>'`. If review cannot proceed, use `flotilla crew stall --reason <infra|scope|decision|access|other> --message '...'`, with `--propose <resume|reduce-scope|fail>` if useful. Do not merge the PR; the human owns merge. Run the applicable crew settlement command as your final act.{% endblock %}
